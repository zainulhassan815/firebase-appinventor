# Agent instructions

This is an MIT App Inventor extension built with Rush.

Before changing the extension, read `.claude/skills/rush/SKILL.md`.
It explains how blocks, dropdowns, events, dependencies and resources work,
and the limits App Inventor imposes.

## Workflow

1. Run `rush build` after every change and fix every error it reports.
2. Read `out/<package>.md` to check that the blocks match what was asked.
3. Tell the user what to test in App Inventor: `rush build` can't run the
   extension.

## Rules

- Blocks are public methods of the `@Extension` class, annotated with
  `@SimpleFunction`, `@SimpleProperty` or `@SimpleEvent`. Use primitive
  types.
- Extensions are non-visible. To show a view, add it to an arrangement passed
  to a block.
- Dropdown enums go in a directory named `helpers`.
- Fire events on the main thread, never while `Screen.Initialize` runs.
- Declare every library in `rush.yml`.
- Don't edit `.rush/` or `out/`: Rush generates them.

## Project notes

- The `Firebase` component connects the default `FirebaseApp`; the others reach
  it through their `Firebase` property. It must implement `Component` directly,
  or Rush can't use it as a property type.
- Every event goes through `Events.fire`: it posts to the main looper and holds
  events until `onInitialize`, which App Inventor calls after
  `Screen.Initialize`. Events fired while `Screen.Initialize` runs are dropped.
- The notification channel id `notifications` is declared as FCM's default
  channel in `src/AndroidManifest.xml` and used in `Notifications.kt`. Change
  both together. The channel is created before every local notification:
  Android drops notifications posted to a missing channel.
- `MessagingService` runs without a screen when the app is closed. It only
  forwards to the active component, so data messages to a closed app are
  silent, as in standard FCM.
- Never add blocks that send messages: sending needs the project's service
  account key, which must not ship in an APK.
- Every library is private (Rush 2.1). DataStore's native code finds
  `androidx.datastore.core` classes by name, so that package keeps its name
  (`original_names`). `datastore-core-jvm` is excluded because Rush resolves
  DataStore in both its JVM and Android forms (rush-cli#87).
- Rush renames Play services' Binder interface names with its classes
  (rush-cli#95), so calls through Play services' service broker fail with
  `Binder invocation to an incorrect interface`. Messaging and Remote Config
  work without them; don't add a feature that needs a Play services API
  (Google Sign-In, location, App Check) until it's fixed.
- `-dontwarn androidx.core.app.PendingIntentCompat`: only Play services'
  error-resolution UI uses it, which this extension never calls. App
  Inventor's AndroidX core 1.9 lacks it, so calling that UI would crash.
- The AI Companion can't load the Firebase AARs. Test with the device
  scenarios: `tests/e2e/run.sh tests/e2e/scenarios/<name>.yail`. They need
  `google-services.json` and a Firebase Admin service account key in
  `tests/e2e/secrets/`.
- Docs: `docs/blocks.md` is generated by `docs/blocks.py` from the built AIX and
  fails on a block without an image or a section. After changing blocks, render
  the images and regenerate it (see `docs/testing.md`).
- Remote Config defaults live in the component, not in the SDK: getters fall
  back to them when Firebase has no value (`VALUE_SOURCE_STATIC`), so
  `SetDefaults` applies at once.
- The sample `samples/firebase-demo` ships with an empty `GoogleServicesFile`.
  `tests/e2e/sample.sh` fills in the secret one and runs it on the device. Its
  blocks are App Inventor's own `.bky` format: edit them in App Inventor and
  export, or keep them valid with `tests/e2e/blocks/compile.js`.
